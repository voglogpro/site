# Квест Бибибайк — Красная Поляна

Отдельный Telegram-бот с Mini App для квеста по трём партнёрским точкам. Участник выбирает места в любом порядке, открывает маршрут в Яндекс Картах или 2ГИС, подтверждает визит физическим QR и получает подарок и 100 Бибибонусов за каждую уникальную точку. После трёх точек система создаёт одну заявку на финальную награду: «Подписка 30 дней» и 300 Бибибонусов.

Проект изолирован от рабочих ботов сотрудников и исполнителей и использует отдельный токен и SQLite-базу.

## Что реализовано

- мобильный Mini App «Квест Красной Поляны»: фирменная карта, реальные QR-штампы, сохранённые промокоды и прогресс квеста;
- свободный порядок прохождения: можно начать с любой точки;
- кнопка «Показать ближайшие» делает разовый расчёт только на телефоне и не отправляет координату боту;
- маршруты от текущего положения через Яндекс Карты и 2ГИС: велосипед, пешком или автомобиль;
- QR-сканер Telegram и ручной резервный код;
- сохранённые подарки, прогресс `0/3 → 3/3`, по 100 Бибибонусов за этап и экран финальной награды;
- серверная HMAC-проверка `Telegram.WebApp.initData`;
- защита от повторной выдачи и атомарное создание одной финальной награды;
- совместимая миграция старой базы: участники, прогресс и действующие QR сохраняются;
- тихое автообновление данных каждые 30 секунд и автоматическая загрузка новой версии после деплоя без ручного свайпа;
- истёкшая незавершённая поездка возобновляется с теми же штампами и подарками, а не блокирует участника навсегда;
- адаптивная CRM со своим независимым дизайном, воронкой, участниками, Бибибонусами и статистикой наград;
- CRM открывается по `/admin.html` и защищена единым паролем `ADMIN_PASSWORD`; после входа сервер выдаёт HttpOnly-сессию;
- несколько QR на одну точку: название, включение/отключение, ручной код, число сканов;
- CRM-карта по умолчанию заблокирована от случайного сдвига, ограничена зоной Красной Поляны, координаты подтверждаются только кнопкой сохранения;
- Leaflet хранится внутри проекта и не зависит от CDN; пользовательская и CRM-карты сохраняют точки и кнопки маршрута даже при ошибке загрузки тайлов;
- 2ГИС MapGL запускается уже с одним `MAPGL_KEY`; переключатель светлой/тёмной карты не пересоздаёт карту, а при наличии пары опубликованных Style ID использует официальный `setStyleById()`;
- за каждой точкой закреплён серверный промокод Бибибайк: он автоматически открывается только после подтверждённого QR, закрепляется за участником и копируется для ввода в приложении Бибибайк;
- после завершения участник вводит телефон и отправляет единственную идемпотентную заявку: телефон и публичный ID `KP-…` сразу появляются в CRM, а после выдачи участнику приходит подтверждение;
- кнопка «Поддержка» открывает квест-бота в режиме диалога: сообщения попадают в CRM, ответы операторов приходят участнику в тот же Telegram-чат;
- кнопка «Поделиться квестом» открывает нативный выбор чата Telegram и отправляет приглашение одним сообщением с видео, полным текстом и кнопкой входа в квест;
- `/health` и `/ready` для BotHost.

## Важное решение по геолокации

Live Location удалён. Бот не принимает и не хранит трансляцию маршрута. Геопозиция используется только по явному нажатию «Показать ближайшие», расстояния рассчитываются локально в Mini App, а координата исчезает после закрытия страницы. Навигатор получает только координаты выбранного места и сам определяет начало маршрута.

Статический QR можно сфотографировать и переслать. Для дорогих наград рекомендуется динамический QR, одноразовый код сотрудника партнёра или проверка активной аренды через API Бибибайк. Текущий QR-only сценарий оптимизирован для простого пилота.

Промокоды этапов одинаковы для всех участников, поэтому квест защищает именно их выдачу: код отсутствует в обычном API-состоянии, открывается после уникального QR один раз на Telegram-пользователя и повторный запрос идемпотентен. От передачи уже увиденного общего кода технически должна защищать система активации Бибибайк: один промокод — одна активация на аккаунт/телефон. Без этой серверной проверки в основном приложении полностью исключить обмен кодами между людьми невозможно.

## До реального запуска

Демо-кампания изначально выключена. В CRM нужно заменить все три точки реальными данными:

1. название и адрес партнёра;
2. координаты внутри Красной Поляны;
3. часы работы;
4. условия подарка;
5. один или несколько физических QR;
6. процесс выдачи подписки на 30 дней и 300 Бибибонусов.

## BotHost

Обязательные переменные окружения:

```text
BOT_TOKEN=...
WEBAPP_URL=https://ваш-домен.bothost.tech
ADMIN_PASSWORD=длинный-уникальный-пароль
# необязательно, только для служебных команд бота
ADMIN_IDS=
QR_SECRET=случайная-строка-не-короче-32-символов
# необязательно: только для будущей замены встроенных промокодов этапов
QUEST_PROMO_POINT_1=
QUEST_PROMO_POINT_2=
QUEST_PROMO_POINT_3=
DATA_DIR=/app/data
WEB_PORT=3000
TIMEZONE=Europe/Moscow
INIT_DATA_MAX_AGE_SEC=43200
ADMIN_SESSION_TTL_SEC=43200
MAPGL_KEY=ключ-доступа-к-MapGL
# необязательно: публичные ID опубликованных дневного и ночного стилей
MAPGL_STYLE_LIGHT=c080bb6a-8134-4993-93a1-5b4d8c36a59b
MAPGL_STYLE_DARK=9643e8da-173b-4359-9fee-8a1fe58e68aa
# необязательная группа/канал для копии уведомления; основная работа идёт в CRM
SUPPORT_CHAT_ID=-1001234567890
SUPPORT_URL=https://t.me/bbbike_support_bot
```

`MAPGL_KEY` хранится только в переменных BotHost и не добавляется в GitHub. Приложение уже содержит опубликованную светлую тему 2ГИС и тёмный Style ID Бибибайк; при необходимости их можно переопределить через `MAPGL_STYLE_LIGHT` и `MAPGL_STYLE_DARK`. Переключение выполняется через `setStyleById()` без уничтожения карты, маркеров и маршрута. На Android и ПК сначала запускается штатный MapGL 2ГИС с облегчённой графикой; при подтверждённом сбое приложение один раз повторяет запуск в WebGL 1, затем показывает понятную ошибку без зависания интерфейса.

Команда запуска: `python main.py`. В BotFather URL Mini App должен совпадать с `WEBAPP_URL`. Рабочую `.db` нельзя хранить в GitHub; для `/app/data` нужен постоянный том. На старте бот выполняет `SQLite quick_check` и пишет в лог путь к БД и безопасные суммарные счётчики — это позволяет сразу увидеть, что после деплоя подключён прежний диск.

Важно для BotHost: на тарифе без постоянного Volume содержимое `/app/data` может быть удалено при перезапуске контейнера. Тогда приложение видит новую базу, снова показывает регистрацию и не узнаёт старые QR. Для рабочего квеста подключите постоянный Volume к `/app/data` и делайте резервные копии средствами хостинга. Эндпоинт `/health` показывает безопасный `database_info`: постоянный идентификатор экземпляра БД, размер и количество участников, сессий и QR — после деплоя эти значения не должны неожиданно обнуляться.

Не меняйте `DATA_DIR`, `DB_NAME` и `QR_SECRET` после запуска кампании: первые два значения определяют рабочий файл БД, а секрет связан с уже напечатанными QR.

## Проверка

```powershell
python -m compileall -q main.py quest scripts
python scripts/smoke_check.py
```

Smoke-тест проверяет повторное открытие той же БД, сохранение настроек и действий, возобновление истёкшей сессии, локальную карту и границы Красной Поляны, подпись CRM-ссылки, все шесть вариантов порядка трёх точек, повтор QR, одноразовое начисление 100 Бибибонусов и единственную выдачу финальной награды.

## Структура

```text
main.py                 запуск polling и aiohttp
quest/config.py         настройки окружения
quest/db.py             SQLite, WAL и совместимые миграции
quest/security.py       Telegram HMAC и QR digest
quest/service.py        свободный прогресс, QR, награды, CRM-аналитика
quest/api.py            Mini App и admin API
quest/bot.py            команды и кнопки Telegram
index.html              Mini App участника
admin.html              CRM администратора; вход по ADMIN_PASSWORD и HttpOnly-сессии
static/app.css          общие стили пользовательского квеста
static/admin.css        независимый старый дизайн CRM
static/vendor/leaflet-1.9.4.asset  локальная браузерная библиотека карты
static/privacy.html     простое объяснение данных
```

Пользовательская карта и карта CRM используют реальные точки из БД и ограничены зоной Красной Поляны. Пользовательский маркер появляется только после явного разового запроса геопозиции и не сохраняется сервером. Для тайлов сохраняется обязательная видимая атрибуция `© OpenStreetMap contributors`; технический префикс Leaflet и его значок не показываются.
